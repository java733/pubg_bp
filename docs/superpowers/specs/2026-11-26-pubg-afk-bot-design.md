# PUBG 挂机脚本 — 设计文档

日期：2026-11-26
状态：待批准

## 1. 意图与动机

在 PUBG PC（Steam，BattlEye）上实现无人值守挂机，尽可能延长单局存活时长以获取 BP / 时长收益。

已确认的关键决定（用户在对话中选定）：

| 维度 | 选择 |
|------|------|
| 客户端 | PUBG PC (Steam) |
| 窗口 | 1920×1080 横屏窗口化 |
| 对局模式 | 单人四排（无队友），优先 FPP；FPP 实现受阻则回退 TPP |
| 接管边界 | 游戏已停在大厅 |
| 挂机目标 | 苟到最后：先落地趴住，再跟毒圈跑（L2） |
| 输入方式 | 纯软件模拟（pydirectinput，scancode） |
| 工程结构 | 分层 + 观察器先行（M0/M1 只识别不发输入） |

手段约束：只做外部视觉（截屏 + 像素/模板匹配 + 颜色断言），不读游戏内存、不注入、不修改游戏文件、不碰网络协议。

## 2. 目标 / 非目标 / 反目标

**目标**

- 自动完成"大厅 → 排队 → 出生岛 → 飞机 → 跳伞 → 落地"全流程，无人工干预。
- 地面阶段：优先进圈，圈内趴住，保持低风险存活。
- F10 启动、F12 立即急停；急停后不残留任何按下的键。
- 状态识别在真实对局样本上准确率 ≥ 98%，且无明显抖动。

**非目标**

- 不做多开 / 账号管理 / 换号。
- 不做对枪、压枪、识别敌人、自瞄。
- 不做反作弊规避、进程隐藏、驱动级输入、DLL 注入、内存读取。
- 不做 L3 级完整决策（地形理解、听声辨位、模型推理）。

**反目标（技术成立但视为失败）**

- 出现"W 键一直按住"导致角色乱跑、坠崖、卡死。
- 状态误判后仍按固定节奏发按键，把角色送进毒圈或送出圈外。
- 脚本在游戏不在前台时仍发输入，影响用户正常操作电脑。
- 运行中途静默挂掉，长时间无动作又不退出。

## 3. 约束与环境事实

- Windows 11，Python 3.12.6 (64-bit)，全局环境当前无任何第三方包，需建 venv。
- 目标进程 `TslGame.exe`，窗口类名 `UnrealWindow`（UE4），标题可能为中文「绝地求生」——**按进程名/类名匹配，不按标题**。
- 游戏以管理员权限运行时，脚本必须同权限，否则全局热键与 `SendInput` 会被 UIPI 静默拦截。脚本启动时自检并提示。
- 高 DPI：启动即设 `SetProcessDpiAwareness(2)`，否则 125%/150% 缩放下坐标整体偏移。
- 截屏：PUBG 窗口化大概率是 flip-model 交换链，`BitBlt` / `PrintWindow` 可能返回全黑。首选 `dxcam`（DXGI Desktop Duplication），回退 `mss`；**M0 必须先验证**。
- 帧率：10–15 FPS 足够（状态变化都是秒级）；单帧处理预算 ≤ 60 ms。
- 显示器必须设为不自动休眠/锁屏，否则截屏为锁屏画面、输入落到锁屏。
- **接管范围**：从「Steam 已登录、游戏已启动并停在大厅」开始。不处理登录、启动器、EULA、反作弊提示与活动弹窗。
- **游戏内设置基线（需一次性锁定）**：简体中文、单人四排 FPP（回退 TPP 时另存一套模板）、HUD 缩放默认、小地图默认尺寸与缩放级别、色盲模式关闭。UI 语言/DLC 变更都会让全部模板失效。
- **采样与标注**：由用户在本机正常对局，观察器自动记录 JSONL 与关键帧；准确率用 `tools/report.py` 随机抽点人工核对，不依赖用户逐帧标注。

## 4. 方案对比与选择

### 4.1 工程结构

- **A 分层 + 观察器先行（选中）**：capture / vision / fsm / action / safety 五层，先交付只读的 M0/M1，用真实样本量出识别率再接动作。风险最低，识别层可离线回放调参。
- B 单文件快速验证：见效快，但 ROI/模板一旦按分辨率与 UI 缩放分叉，或加防抖、冷却时就失控，容易在识别未调准时乱按键。
- C 一次性完整版：把动作层与未经验证的识别层同时交付，失败时无法定位是"看不见"还是"点不对"。

选 A 的理由：纯视觉方案能否成立，80% 取决于识别准确率；先把它变成可度量的数字，再投入动作层。

### 4.2 截屏

- **dxcam（DXGI，选中，需 M0 验证）**：GPU 侧复制，延迟低、不依赖窗口消息。
- mss（GDI）：简单，flip-model 窗口可能黑帧，作为回退。
- `PrintWindow(PW_RENDERFULLCONTENT)`：对 UE4 常无效，仅作兜底尝试。

### 4.3 识别

- **模板匹配 + 颜色占比 + 几何检测（选中）**：ROI 固定后成本低、可解释、易离线调参。
- OCR（倒计时数字、存活人数）：只在模板不够时对极小 ROI 补充使用，不作为主路径。
- CNN / YOLO：过重，且样本采集成本远超收益。

### 4.4 输入

- **pydirectinput（scancode 级，选中）**：绕过部分 DirectInput 兼容层，鼠标用相对移动。
- `SendInput` 直调：等价但少一层封装，无额外收益。
- 硬件 USB HID：已被用户排除。

### 4.5 进圈（L2）

- **地图标点 + 罗盘闭环（用户提出，选中）**：右键在圈边内侧打航点，罗盘黄标作视觉反馈闭环转向。不需要绝对朝向、不需要灵敏度标定，误差逐帧收敛。
- 小地图圈心向量 + 罗盘刻度测偏航（弃）：要标定"鼠标像素 → 角度"，且刻度匹配误差会随转向累积。
- 纯小地图视觉导航（弃）：圈心经常落在小地图视野之外，信息不足。

## 5. 架构

### 5.1 分层与数据流

```
capture ──帧(np.ndarray)──> vision ──StateObservation──> fsm ──Command──> action
   ^                          ^                            |
   └──── 前台/客户区矩形 ──────┘         safety ──停止/权限/心跳──┘
```

- capture：每轮取一帧客户区图像（BGR），附带时间戳；不做任何处理。
- vision：纯函数式，输入帧 + 配置，输出 `StateObservation(state, scores: dict, confidence)`。不持有状态。
- fsm：持有当前状态、驻留时长、投票缓冲；输出语义命令（`CLICK_START`、`JUMP`、`MOVE_TO_ZONE(bearing_deg)`、`PRONE`…），不直接碰键鼠。
- action：把命令翻译为键鼠原语，带前置条件校验与冷却。
- safety：独立热键线程 + 心跳看门狗 + 前台校验 + 退出时释放全部按键。

### 5.2 状态定义

| 状态 | 主要锚点 |
|------|----------|
| `LOBBY` | 大厅按钮/模式文字模板，主色 |
| `QUEUE` | 匹配中/加载中：加载条、地图加载图、黑屏（无 UI 也算本状态） |
| `SPAWN` | 出生岛倒计时区域变化、玩家列表 UI |
| `PLANE` | 「按 F 跳伞」提示模板、小地图航线段 |
| `FREEFALL` | 高度条/降落伞图标、天空主色 |
| `GROUNDED` | 血量条、小地图、存活人数 |
| `MARKING` | 地图 UI 已打开（全屏地图锚点）、白圈 |
| `RUNNING` | 非视觉识别态，`GROUNDED` 的 FSM 内部子模式；使用罗盘黄标、血量条锚点 |
| `DOWNED` | 击倒标记/血量条变色/爬行姿态（单人四排无队友，只需处理流血到死） |
| `RESULT` | 结算文字模板 |
| `UNKNOWN` | 以上全部低于阈值 |

转移：`LOBBY → QUEUE → SPAWN → PLANE → FREEFALL → GROUNDED → RESULT → LOBBY`；`GROUNDED ↔ MARKING ↔ RUNNING`；`GROUNDED ↔ DOWNED`；任何状态 → `UNKNOWN`。

`QUEUE` 是必要的过渡态：匹配与加载期间会连续数秒无 UI，若把它计入 UNKNOWN 会导致告警误触发，也会污染识别率分母。

`MARKING` / `RUNNING` 是 `GROUNDED` 的子状态，单独列出是为了让动作层的"抢占式急停"有明确落点：`RUNNING` 中检测到受击/新圈/地图被意外打开时，一律先释放 W 再重新决策。

各状态策略：

| 状态 | 动作 |
|------|------|
| `LOBBY` | 命中开始按钮则点击一次，冷却 5 s |
| `QUEUE` | 不动作；超过 10 min 才告警（FPP 队列可能很长） |
| `SPAWN` | 不动作，等自动进飞机 |
| `PLANE` | 起飞后固定延迟按 F 跳伞（M3 再按航线优化） |
| `FREEFALL` | 视角压低 + 按住 W 直至落地 |
| `GROUNDED` | 圈内则趴下 + 定时微动；圈外或圈即将更新则转 `MARKING` |
| `MARKING` | 开图 → 找白圈 → 标最近圈边 → 关图 → 转 `RUNNING` |
| `RUNNING` | 罗盘闭环对齐 → 前进 → 进圈边则停，回 `GROUNDED` |
| `DOWNED` | 朝圈内方向爬行 ≤ 2 s，然后趴住 |
| `RESULT` | 点击返回大厅，回 `LOBBY` |
| `UNKNOWN` | 不动作 |

### 5.3 识别与防抖

- 灰度模板匹配，`TM_CCOEFF_NORMED`，单锚点阈值初值 0.85。
- 每状态 2–4 个锚点，**多锚点投票**：至少 2 个命中且总分最高者胜出。
- 连续 3 帧一致才切换状态；非 UNKNOWN 状态最短驻留 500 ms。
- 颜色断言用 HSV 区间 + 区域像素占比（如血量条白/红占比），不用单点精确 RGB，避免压缩与抗锯齿误判。
- 全部低于阈值 → `UNKNOWN`，**UNKNOWN 期间不发任何输入**。

### 5.4 进圈（L2）：地图标点 + 罗盘对齐

思路由用户提出：不测绝对朝向，用"地图右键标点 → 罗盘黄标 → 闭环转向"来对准圈。

**前提已实测确认（2026-11-26）**：当前版本地图右键可放置航点；航点在顶部罗盘上显示为黄色标记，并随转向沿罗盘条滑动。因此整个方案不依赖任何推测的 UI 行为。

1. **触发**：`GROUNDED` 中位于圈外，或检测到白圈圆心/半径变化超过阈值，或距上次标记超过 20 s 时进入 `MARKING`。
2. **开图**：按 M，等待地图 UI 锚点命中（全屏地图模板），超时 1.5 s 判失败。
3. **找圈**：在地图 ROI 内做白圈检测——颜色分割得到高亮环带，再做圆拟合（HoughCircles 优先，失败退回最小二乘），输出圆心与半径。**只用几何，不用固定坐标**，因为地图缩放/平移会被游戏记住。
4. **定玩家**：地图 ROI 内匹配玩家箭头模板；找不到则以"地图视图中心"为玩家位置（开图默认以玩家为中心）。
5. **选点**：沿"玩家 → 圆心"方向取 `0.9R` 处，即离玩家最近的圈边内侧；点落在屏幕外则取地图 ROI 内最接近的可点位置。
6. **标点**：在该像素右键点击（PUBG 地图右键即放置航点）。
7. **关图**：按 M，等待地图消失；关图失败视为状态异常，回 `GROUNDED`。
8. **对齐**：`RUNNING` 中在罗盘 ROI 内检测黄色标记的 x 坐标，与罗盘中心比较：
   - 差 |dx| ≤ 死区（默认 6 px）→ 视为已对准，转入前进；
   - 黄标在左 → 小步左转，在右 → 小步右转，单帧最多 8 px；
   - 全程闭环，**不依赖鼠标灵敏度标定**，也不依赖罗盘刻度识别。
9. **前进**：对准后按住 W，每 2 s 复测罗盘与最小地图距离，偏差超出死区则先松开 W 重新对齐。
10. **停止**：小地图上 `dist(player, circle_center) ≤ R − margin`（margin 默认 0.08R）即停止前进，回 `GROUNDED` 并趴下。
11. **兜底**：
    - 罗盘连续 2 s 检测不到黄标（标记在身后、超出罗盘显示范围）→ 按固定方向扫视，最多 3 s；仍找不到则重新标点。
    - 前进中 10 s 内最小地图距离无变化（卡地形/撞墙/被围）→ 停 W，随机小角度绕行 1 s 再继续。
    - 连续 2 次标点失败或 3 次进圈失败 → 停止跑动，就地趴下，等下一轮触发。
    - 血量 3 s 内下降超过阈值 → 立即停 W、趴下，不再主动移动。

### 5.4.1 可配置锚点

罗盘 ROI、黄标 HSV 区间、死区像素、白圈 HSV 区间、玩家箭头模板、地图 ROI、`0.9R`/`0.08R` 系数、各类超时全部写入 `config/anchors.1920x1080.json`，代码中不出现魔法数字。配套 `tools/overlay.py` 把当前帧上所有 ROI、命中锚点、黄标 x、圈心圆实时叠加显示，用于逐项对位调试。

### 5.5 动作层

- 所有按键使用上下文管理器：进入按下、退出必释放，异常路径同样释放。
- 每个动作执行前重校验状态（动作所属状态已变则丢弃），并带冷却时间。
- 只读/写状态分离：观察器模式下 action 层替换为空实现，保证同一套 fsm 代码可直接用于 M1 与后续版本。
- 鼠标移动用相对位移小步长连续移动（每次 ≤ 40 px），兼容 RawInput。
- 输入前校验前台窗口为游戏本体，否则暂停并记日志。

### 5.6 安全层

- F10 启动 / F12 急停，`keyboard` 全局钩子，独立线程设置 `threading.Event`。
- 看门狗：主循环 2 s 无心跳则强制释放全部按键并停止。
- `atexit` + 未捕获异常钩子：释放全部按键、写日志。
- 会话上限（默认 8 h）、单状态超时（`FREEFALL` > 3 min = 异常）、`UNKNOWN` 连续 10 s 且不属于 `QUEUE`/`LOADING` 特征 = 暂停告警。
- 所有决策写 JSONL 日志，含帧号、状态、各锚点分数、执行的命令；关键帧按需存盘用于离线复盘。

## 6. 里程碑与验收标准

| 里程碑 | 内容 | 验收 |
|--------|------|------|
| M0 | 句柄/客户区/DPI + dxcam/mss 各截一帧存盘 | 画面内容正确非黑帧；单帧 ≤ 30 ms；窗口异动后仍能截准 |
| M1 | 观察器：capture + vision + fsm，不发任何输入 | 连续 10 局 JSONL；每局随机抽 20 个时间点人工判定（共 ≥ 200 点），识别一致率 ≥ 98%（`QUEUE`/加载/黑帧不计入分母）；同一状态片段内误切换 ≤ 2 次；非加载期 `UNKNOWN` 占比 < 1% |
| M2 | 动作层 + 安全层，L1 落地趴住 | 连续 3 局自动进对局并存活至首个安全区；无卡键、无越界输入 |
| M3 | L2 进圈：地图标点 + 罗盘闭环对齐 | 连续 5 局中 ≥ 4 局成功进入圈边（首次进圈 ≤ 90 s）；黄标丢失、标点失败均能回退趴下；全程无卡键、无地图残留打开 |
| M4 | 无人值守长跑 | 8 h 连续运行，异常均能自停并留证据 |

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| flip-model 导致截屏全黑 | 项目不成立 | M0 前置验证；dxcam → mss → PrintWindow 逐级回退；全部失败则终止并向用户说明 |
| 封号 | 账号损失 | 不读内存不注入，但自动化本身违反条款，风险不可消除；用户自行承担 |
| 权限/前台不匹配导致输入失效 | 看似运行实则无效 | 启动自检管理员权限；每帧校验前台；失效即告警 |
| 状态误判 | 乱跑、毒圈送死 | 多锚点投票 + 连续帧 + 最短驻留；UNKNOWN 不动作；动作前重校验 |
| 小地图圈检测失败（缩放/载具/遮挡） | 跑错方向 | 保守回退趴下；圆检测双重策略；连续失败计数 |
| 按键卡住 | 角色失控 | 上下文管理器 + 看门狗 + atexit 释放 |
| 显示器休眠/锁屏 | 数据全废 | 运行前提示关闭休眠；锁屏检测到前台非游戏即暂停 |
| 分辨率或 UI 缩放变化 | ROI 全偏 | 配置按分辨率键控；启动时校验客户区尺寸并拒绝不匹配配置 |
| FPP 队列人数少、排队长 | 长时间停在 `QUEUE`，被误判为卡死 | `QUEUE` 超时放宽到 10 min；识别到加载/匹配特征时不触发 UNKNOWN 告警 |
| 被击倒误判为正常存活 | 该爬不爬、该等不等 | `DOWNED` 单独一套锚点；`GROUNDED` 判定同时要求血量条为正常态 |
| 罗盘上找不到黄标（标记在身后） | 原地无限转圈 | 2 s 未检出即按固定方向扫视 3 s；仍无则重新标点，两次失败就地趴下 |
| 地图缩放/平移被游戏记住 | 白圈在屏幕上的位置与大小不定 | 只用几何圆检测，不用固定坐标；进圈距离统一在小地图上算，不跨图换算比例 |
| 游戏版本改动航点交互或罗盘样式 | 标点失效 | 右键航点与黄标颜色全部走配置；改版后按 5.4.1 重新标定并跑一遍回归样本 |

## 8. 留给 builder 的决定（我的预设，可改）

- 依赖用 `pyproject.toml` + venv 管理；版本在实现时锁到当时最新稳定版。
- 日志为 JSONL，一行一决策。
- 所有 ROI 与阈值以 1920×1080 为基准，由 `tools/pick_roi.py` 生成，不手写猜数值。
- 动作节奏的等待时间取固定值 + 小抖动，仅用于避免帧边界误判，不做反检测用途。
- 跳伞时机用"起飞后固定延迟 + 固定方位"起步，M3 再基于航线小地图做优化。
- 观察器与完整模式共用同一 fsm，动作层以空实现注入。
